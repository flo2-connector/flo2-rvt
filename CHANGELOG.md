## 0.10.0 (unreleased)

A stair run is named by its climb, with its stair. flo2-rvt 0.9.0's proof in real Revit (2026-11-04, job rvtj_70f663c31917b1c1, Autodesk's sample house lowered 9 3/8 in) named the living-room stair by its climb, 541.7 to 412.5 mm, and its run beside it by its box, "172.2 mm shorter": add-in 0.8.0 gave a climb only to Revit's Stairs class, and a run is a StairsRun. Revit's own IFC of the run gives the same climb as the stair's. The tests had asserted the run's box words, written from the report's output. Root cause in flo2-rvt's design (`fact:a-reshaped-stairs-run-is-still-named-by-its-box-not-its-climb-2026-11-04`). Add-in 0.9.0; report version 2 still (fields added, none changed); contract v3 unchanged; change-list schema unchanged.

- **A stair run's climb**: a reshaped run gives `run`: its actual risers and its climb before and after (`StairsRun.ActualRisersNumber`, and `StairsRun.Height`, "the elevation span between run's base elevation and top elevation"); a run whose risers or height changed is reshaped even when its box did not.
- **What it belongs to**: a run or a landing names its stair (`part_of_element_id`, from `GetStairs()`), so a stair and its run read as one.
- **The words**: the README and the edit tool's description say so.
- **Add-in 0.9.0**: an app set up with add-in 0.8.0 (flo2-rvt 0.9.x) reads `outdated` until its next one-time setup, which flo2.io offers.
- **Tests**: the proof's run, with its risers and height as Revit's IFC gives them, carries its climb and its stair; every stair and stair run reshaped carries a climb (anything that climbs is given its climb, not its box alone); a run whose climb or risers changed inside the same box is reshaped, rounding is not; report.json reads both back. They cannot compile on 0.9.0 (`RunMeasure` is not there).
